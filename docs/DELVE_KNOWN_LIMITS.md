# Fast Delve M1 known limits

This document records what the M1 loader and runtime establish for an untrusted pack. “Covered” means a deterministic test exercises the stated property; it is not a claim about every pack accepted by the schema.

## Guarantees M1 checks

Terminal input handling is total: it never crashes on any input, and malformed Unicode is treated as an unknown verb. M1 never received a Sandy PASS (three FAIL rounds); residual findings were fixed without a fourth pass. Ask for the review history in `evidence/dossiers/sol_m1_*.md`.

| Property | M1 guarantee | Evidence |
|---|---|---|
| Pack shape and closed mechanics | Required fields, IDs, references, vocabularies, effect shapes, clue sources, bank fallbacks, and engine structural keys are validated before play. | `tests/test_delve_pack.py`, `tests/test_delve_content.py` — covered for named mutations and shipped content. |
| Effect ownership | Effects execute in `Engine`; dead and victory terminal states cannot be assigned by an effect. | `tests/test_delve_pack.py::test_dead_effect_is_rejected_in_any_effect_list` — covered for reader, hazard, intent, threshold, and payoff effects. |
| Terminal event interface | Victory and death use `terminal.victory` and `terminal.death`; retry uses `terminal.retry`. | `tests/test_delve_pack.py::test_terminal_event_keys_are_fixed_interface_keys` — covered, including the shipped pack. |
| Gate and clue route reachability | A gate opens in the reachability model only when its flag producer or matching `open_exit` effect is reachable without crossing that gate. Reachable clue readers and victory destinations are checked. | `tests/test_delve_pack.py::test_self_locked_clue_gate_is_unreachable` and `test_static_unreachable_victory_mutant_is_killed` — covered for direct cycles and unreachable destinations. |
| String encoding and JSON decoding | Strings in dict packs and decoded JSON must encode as UTF-8; lone surrogates are rejected with `E_SCHEMA` and a path. Duplicate object keys and nonstandard JSON constants are rejected. | `tests/test_delve_pack.py::test_surrogate_strings_rejected_with_schema_path` and `test_strict_json_rejects_duplicate_keys_and_nonstandard_constants` — covered for escaped title surrogates, duplicate keys, and `NaN`. |
| Turn and random ownership | Deterministic combat uses the run RNG; invalid named combat targets do not advance state or draw dice. | `tests/test_delve_combat.py` — covered for absent target and multi-enemy attack, shove, and throw-at selection. |
| Shipped interaction cues | The ring is consumed on a successful handover; takeable objects are marked `(get)`; named enemies can be inspected without an engine action. | `tests/test_delve_terminal.py`, `tests/test_delve_render.py`, `tests/test_delve_content.py` — covered on representative paths. |

## Properties not proved by M1

| Limit | Current boundary | Evidence / status | Closure milestone |
|---|---|---|---|
| Conditional flag producers | Reachability is an abstract fixed point over reachable rooms, readers, hazards, enemy intents, clocks, and clue payoffs. It does not model every runtime ordering, one-shot interaction, item possession sequence, enemy survival requirement, or mutually exclusive state combination. | Direct self-lock and simple reachable producers are tested; full accepted-pack equivalence to runtime is **not covered**. | M4: student-pack property-based fuzz harness, with a written property list. |
| Optional metadata shape | `meta` is checked as an object, but its keys and values are not restricted to the documented authoring receipt field. | **Not covered:** no test rejects unknown metadata keys or non-string receipt values. | M4: student-pack property-based fuzz harness, with a written property list. |
| Event keys and renderer coupling | Terminal keys and engine structural keys are checked. A custom pack can still declare arbitrary content keys and prose whose semantics do not match the event that emits them. Every accepted pack/event/render path is not exhaustively executed. | Structural-key and placeholder checks are covered; exhaustive event-key coupling is **not covered**. | M4: student-pack property-based fuzz harness, with a written property list. |
| Unicode display behavior | Invalid UTF-8 scalar strings are rejected. Unicode normalization, combining marks, bidirectional controls, terminal escape/control characters, and terminal width are not normalized or screened. | Lone-surrogate title is covered; other Unicode display edge cases are **not covered**. | M4: student-pack property-based fuzz harness, with a written property list. |
| Resource use | JSON syntax and field shape are checked, but there are no practical upper bounds for pack bytes, number of rooms/objects/effects/variants, text length, clock maxima, or numeric magnitudes. A valid extreme pack can consume excessive memory or time during load, status rendering, or play. | Ordinary shipped pack and fixed mutation samples run; resource exhaustion is **not covered**. | M4: student-pack property-based fuzz harness, with a written property list. |
| Hostile bank prose | Bank text is treated as authored display text with validated placeholders. The loader does not establish truthfulness, safety, readability, or that prose avoids misleading tactical advice. | Silver-leaf telegraphs are checked in shipped content; arbitrary hostile or deceptive prose is **not covered**. | M4: student-pack property-based fuzz harness, with a written property list. |
| General accepted-pack crash freedom | Deterministic tests and the supplied mutation run cover selected schema and play paths. They do not enumerate every accepted pack graph, action sequence, event ordering, or state combination. | Supplied fuzz script is a finite sample, not a proof; universal crash freedom is **not covered**. | M4: student-pack property-based fuzz harness, with a written property list. |

M4's property list should state, at minimum, the invariants checked after every generated load and action: loader errors are coded `PackError`s; accepted packs do not crash on generated valid actions; invalid actions preserve game state, turn, clocks, and RNG; terminal state follows validated victory or HP-zero death; all emitted keys and slots render through declared bank entries; and reachable clue/gate/victory claims agree with an independently computed runtime model.
